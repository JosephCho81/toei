# 결정 이력 — 담당자가 확정한 것

> **언제 읽나**: 「이거 왜 이렇게 돼 있나」·「바꿔도 되나」를 물을 때.
> 여기 있는 것은 **다시 뒤집지 말 것.** 뒤집으려면 담당자 재확인이 먼저다.


담당자 요청과 답변을 코드·라이브 DB에 적용한 것이다. **다시 뒤집지 말 것.**

| | 확정된 것 | 어디에 |
|---|---|---|
| 1 | 남은 돈을 넷으로 가른다 — 연체(달 넘김) · 이번 달 지급 중 · 지급금 차이(35차까지) · 기일 미도래 | `bucketOf()` + `payments.test.ts` |
| 1 | 빨강은 기일 + **7일**(`DUE_GRACE_DAYS`)을 넘긴 줄에만. 월별 표에 이번 달 지난 기일도 넣는다 | `PaymentSchedule` |
| 2 | **36차부터 엑셀 청구금액을 비웠다** (36~39차 4건). 청구값은 검수 후 화면에서 따로 넣는다 | 실행 완료 |
| 3 | 정산 비교 열에 수입금액($) 추가, 실지급일은 펼침으로 | `CompareTable` |
| 5 | **최종정산 29~34차를 신방식으로 전환** — 공급가 100원 절사. 1~28차는 그대로 | 실행 완료 |
| 6 | 합산 정산건은 차수별 청구액을 넣어 「청구−계산」으로 본다 | 입력 대기 |

### 경계는 차수로 자른다 — 기간이 아니다

「지금까지 정산된 35차까지를 지급금 차이로 계산. 연체는 이번달 지급 중인 금액을 제외하고 계산.
달이 넘어가는 연체 항목에 대해 지체상금 쪽으로 입력 예정.」(담당자 2026-09-10)

「1년 경과」 같은 기간 규칙으로 자르면 지금 정상인 37·38차가 1년 뒤 조용히 연체에서
빠져나가 **진짜 연체가 화면에서 사라진다.** 그래서 `SETTLED_THROUGH_ROUND = 35` 로 못 박았다.

35차까지의 남은 금액 5건 161,821,438원 중 **2차 131,123,840 · 3차 30,000,001 은 이미 지급됐다** —
개인 통장 등으로 나갔다는 담당자 확인이 있다. 지급 기록을 넣으면 697,597원만 남는다.
**실제 지급일과 금액이 필요하다.**

### 36차부터 청구금액을 비운 뒤의 기준

비운 4건: 36차 124,384,618 · 37차 207,895,876 · 38차 136,883,194 · 39차 136,822,694.
되돌릴 값은 `supabase/seed/interim_invoiced.sql` 과 `supabase/manual/backup_20260910_before.json` 에 있다.

청구액이 없으면 **계산값이 잔액의 기준**이 된다(`basisKrw`). 0 으로 두면 36차 이후가
통째로 화면에서 사라진다. 36차는 126,431,030 − 116,431,030 = **10,000,000원**이 남고,
이는 담당자가 예시로 적은 「1,000만원 지급 필요」와 일치한다.

### 최종정산 29~34차 신방식 전환 (실행 완료)

구방식(`inclusive`)은 절사가 **최종가**에 걸린다 — 부가세를 분리할 수 없어 공급가 칸이 없다.
화면 라벨은 「공급가에 적용」이었고 라이브 33건이 전부 구방식이라 **전 건이 라벨과 다르게** 돌았다.
담당자 지적으로 29차부터 신방식(`exclusive` + `floor_100`)으로 넘겼다. **1~28차는 손대지 않는다.**

| 차수 | 전 | 후 | 차이 |
|---|---|---|---|
| 29 | 2,828,800 | 2,828,760 | −40 |
| 30 | 2,858,100 | 2,858,020 | −80 |
| 31 | 1,964,700 | 1,964,710 | +10 |
| 32 | 3,117,900 | 3,117,840 | −60 |
| 33 | 5,080,200 | 5,080,240 | +40 |
| 34 | −290,900 | −290,840 | +60 |

여섯 건 합계 −70원.
1~28차는 여전히 구방식이므로 **그 화면의 절사 라벨은 「최종가에 적용 (구방식)」으로 뜬다.**

### 합산 정산건 — 담당자 제공 수치 (2026-09-10)

| 묶음 | 청구 | 지급 | 청구−지급 | 청구−계산 |
|---|---|---|---|---|
| 1, 3~8차 | 19,118,268 | 17,242,417 | 1,875,851 | −818,231 |
| 9~15차 | 5,703,470 | 5,703,470 | 0 | −549,968 |

통장 근거: 2023-02-23 출금 17,242,417 「하르탈레가 정산 (2차 제외 1~8차)」 /
2023-12-29 출금 9,366,722 「환차손」 / 2024-01-05 입금 3,663,252 「환차익」.
**환차익 3,663,252 는 9차(−3,221,209) + 15차(−442,043) 와 원 단위까지 일치한다.**

세 건 모두 `payment_allocations` 에 `kind='other'`(차수 없음)로 잡혀 있어 1~15차 최종정산
지급액이 0 으로 보인다. **차수별 청구액을 넣고 배분을 나눠 붙여야 한다** — 묶음 합계만으로는
차수별 배분을 지어낼 수 없다.
