# 남은 작업

> **언제 읽나**: 「지금 뭐가 남았나」를 물을 때. 진행 상황이 바뀌면 여기부터 고친다.

## 진행 현황 (2026-09-10 기준, 2026-09-18 추가분 포함)

### 담당자 진행 중

0. **3·4·5차 비용 항목 확인 (2026-09-18 직원 회신)** — 9/17 20:38~20:44(KST)에 중간·최종정산 6건을
   확정했으나 항목은 9/11 저장본 그대로다(확정 저장 순서 결함, 2026-09-18 수정 `4374531`).
   그날 항목을 고친 뒤 확정했다면 수정분이 빠졌다 — 잠금 해제 후 재입력·재확정.
   회신 문서: https://claude.ai/artifact/UM8Um7mFuKgzVe2iBzykBm

1. **확정금액 재입력 37개 차수** — 09-04 소급 미반영분. 화면 「계산값」 열이 목표값이다 (`docs/차수-이슈.md`)
2. **1~10차 재입력** — 서류 미비 보완. 2차 통관보수 누락 / 5·6·7차 트럭비 누락.
   **2·6·7차는 구방식이라 재입력 시 확정금액이 +1,100만~1,200만씩 뛴다** — 세금계산서 정합 확인이 먼저다
3. **35·38·39차 원본 청구서** — 실제 청구가 계산보다 각각 −5,483,717 / −1,164,056 / −1,169,556.
   35차는 확정금액이 계산값과 일치하므로 **계산이 아니라 청구가 틀린 건**이고,
   38·39차는 금액이 거의 같아 같은 원인으로 보인다. 셋 합쳐 약 780만원
4. **20·25·42차 서류** — 25차는 22차 자료가 잘못 와 있어 재요청 중. 44차는 입항 이후
5. **지체상금 입력** — `/settlements/penalty` 에서 수기 입력. 산식은 미확정.
   통장 원장에 지체상금으로 보이는 기록이 5건 있다(「영업수수료(실제 지체상금)」 4건 5,046,032원
   + 상계된 5,666,612원). 이걸 지체상금 항목으로 옮길지 판단 필요.
   **부가세 포함으로 적을지도 미정이다** — 지급 현황은 원화 금액을 전부 부가세 포함으로 표기하는데
   지체상금은 산식이 없어 담당자가 적는 금액의 기준이 정해져 있지 않다. 첫 건 입력 전에 정할 것(현재 0건)
6. **최종정산 실제 청구액** — `038` 로 칸만 만들었고 **33건 전부 비어 있다.**
   값이 없어 최종정산 화면이 전부 「청구 전」이다.
   **입력칸은 2026-09-10 에 만들었다** — 정산 비교 화면에서 차수를 펴면 나온다
7. **중간정산 36~39차 청구값** — 엑셀값을 비웠으므로 검수 후 같은 자리에 넣는다.
   넣기 전까지는 계산값이 잔액 기준이다
8. **남은 지급금 차이 3건** — 4차 606,823 · 12차 41,566 · 22차 49,208.
   2·3차는 2026-09-10 에 원장에 넣어 닫혔다 (`docs/지급-원장.md`)

### 착수 대기 — 직원 요청 (2026-09-22)

- **중간·최종정산 화면에 차수 · P/O · B/L 표기** — 서류 대조용. B/L 은 `containers` 에서, 여러 건이면 모두
- **중간정산 문구·구성** — 그룹 A 「소계 (vat 제외)」. 그룹 B 설명 3줄 추가, 입력 행 「부가세 → 수입부가세」,
  체크 열은 **부가세 / 수입부가세 / 관세 3열**(사용자 확정), 통관보수료·검역수수료·정밀검역비 부가세 기본 체크,
  「소계 (vat 포함)」 — 세 항목은 10% 가산해 소계에 넣는다. **입력값은 여전히 공급가**(부가세 제외)다
- **계산 결과 재배열** — 통관 소계(vat 포함) · 부가세(수입부가세 + 국내발생비용 부가세) · 관세(0 아니면) /
  공급가 · 부가세 · 관세 · 합계. 공급가 산식은 그대로라 금액은 바뀌지 않아야 한다 — 회귀 테스트로 못 박을 것
