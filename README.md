# 토에이산교↔한국에이원 수입 정산 관리 시스템

토에이산교 코리아와 한국에이원 간 장갑 수입 거래의 정산 업무를 웹으로 자동화한 시스템.

**대금은 한국에이원 → 토에이산교 방향으로 흐른다.** 토에이가 수입대금과 LC 결제비용을
먼저 치르고 마진을 얹어 에이원에 청구한다 — 중간정산·최종정산 모두 **금액이 양수면 에이원이
토에이에 낼 돈**이고, 음수(환급)일 때만 토에이가 에이원에 돌려준다. 리포트·PDF 의
「한국에이원 → 토에이산교 지급」이 같은 규약이며, 발행자는 ㈜한국에이원이다.
**화면 라벨을 반대로 달지 말 것** — 2026-09-04 까지 지급 현황 KPI·표가 뒤집혀 있었다.

**프로덕션 URL**: https://toei-a1-settlement.vercel.app

## 환경변수

`.env.local.example` 참고:

```env
NEXT_PUBLIC_SUPABASE_URL=       # Supabase 프로젝트 URL
NEXT_PUBLIC_SUPABASE_ANON_KEY=  # Supabase anon key
SUPABASE_SERVICE_ROLE_KEY=      # Supabase service_role JWT
BOK_API_KEY=                    # 한국은행 ECOS (클로징 환율)
UNIPASS_API_KEY_CARGO=          # 관세청 유니패스 API001 화물통관진행정보
UNIPASS_API_KEY_FXRATE=         # 관세청 유니패스 API012 관세환율 정보
```

유니패스 인증키는 unipass.customs.go.kr 회원가입 후
**My메뉴 → 서비스관리 → OpenAPI 사용관리**에서 API 별로 따로 발급받는다 (즉시 승인).

## 로컬 실행

```bash
# 1. 패키지 설치
npm install

# 2. 환경변수 설정
cp .env.local.example .env.local
# .env.local 편집 후 실제 값 입력

# 3. 마이그레이션 적용 (Supabase CLI 필요)
npx supabase db push

# 4. 개발 서버 실행
npm run dev
```

로컬: http://localhost:3000

## 문서 지도 — **필요한 것 하나만 읽는다**

이 저장소의 문서는 **질문 하나에 파일 하나**로 갈라 두었다. 전부 읽지 말 것 —
매 턴 컨텍스트에 다시 실려 비용이 곱으로 늘어난다 (`docs/토큰-절감.md`).

| 무엇을 물을 때 | 읽을 파일 | 크기 |
|---|---|---|
| 금액이 어떻게 계산되나 | `docs/계산-규약.md` | ~100줄 |
| 이 차수가 왜 안 맞나 | `docs/차수-이슈.md` | ~190줄 · **차수 번호로 grep** |
| 이거 왜 이렇게 돼 있나, 바꿔도 되나 | `docs/결정-이력.md` | ~70줄 |
| 지금 뭐가 남았나 | `docs/남은-작업.md` | ~60줄 |
| DB·계산 코드의 함정 | `docs/시스템-상태.md` | ~80줄 |
| 화면을 고쳐도 되나 | `docs/화면-규칙.md` | ~90줄 |
| 지급 입력·배분·잔액 | `docs/지급-원장.md` | ~100줄 |
| 통관일·환율·선사·B/L | `docs/추적-연동.md` | ~55줄 |
| 스키마·마이그레이션 | `docs/마이그레이션.md` | ~40줄 |
| 세션 비용을 줄이려면 | `docs/토큰-절감.md` | ~40줄 |

**읽는 법**: 파일이 60줄을 넘으면 통째로 열지 말고 목차부터 본다.

```bash
grep -n '^#' docs/차수-이슈.md      # 목차와 줄번호
sed -n '40,72p' docs/차수-이슈.md   # 필요한 절만
grep -n '37차' docs/차수-이슈.md     # 차수로 바로 찾기
```

`docs/정산-현황.md` 는 위 표와 같은 내용의 색인이다. 둘 중 하나만 보면 된다.

## 화면 구성 — 한 줄 요약

화면마다 답하는 질문이 다르다. **같은 값을 여러 화면에 늘리지 말 것.**
자세한 규칙과 그 이유는 `docs/화면-규칙.md`.

| | 답하는 질문 | 독자 |
|---|---|---|
| **지급 현황** (`/payments`) | 돈이 실제로 오갔나, 얼마가 남았나 | 양사 대표 · 첫 화면 |
| **정산 비교** (`/settlements/*`) | 청구가 계산과 맞나, 어디가 얼마나 어긋났나 | 담당자 · 대사 |
| **정산 현황** (`/dashboard`) | 돈이 언제 오가나, 무엇이 늦었나 | 담당자 · 물류·정산 일정 |
| **거래 목록** (`/transactions`) | 무엇을 얼마에 샀나, 어디가 틀렸나 | 담당자 · 품목·금액 대조 |
| **기준정보** (`/manufacturers`) | 제조사 · 품목 마스터 | 담당자 |

- 첫 화면은 지급 현황이다 — `/` 와 `/(app)` 은 `/payments` 로 보낸다
- 왼쪽 메뉴는 **다섯 칸뿐**이다. 같은 질문을 대상만 바꿔 묻는 화면은 사이드바가 아니라 **화면 안 탭**이 가른다
- **금액이 셋이다** — 실제 청구액(`invoiced_amount_krw`) / 담당자 확정금액(`confirmed_amount_krw`) /
  시스템 계산값(저장하지 않는다). **차이도 셋**이라 한 칸에 합치지 말 것 (`docs/화면-규칙.md`)

## 현재 미구현 항목

| 항목 | 상태 |
|------|------|
| 로그인/인증 | 비활성화 중 (`proxy.ts` AUTH_DISABLED 블록), 추후 별도 진행 |
| 최종정산 실제 청구액 | 입력칸은 있으나 **33건 전부 비어 있다** — 화면이 전부 「청구 전」으로 뜬다 |
| 중간정산 36차 이후 청구액 | 엑셀값을 비웠다 (2026-09-10). 검수 후 화면에서 넣는다 |
| 지체상금 산식 | 미확정. 금액을 수기 입력한다 (`037` 주석 참조) |
| `vat_mode` 전환 UI | 없다. 구방식 정산은 재입력하거나 DB를 직접 고쳐야 한다 |
